# 🚀 Бърза Настройка - Storage Bucket Политики

## Проблем
Грешка при качване на файлове: **400 Bad Request**

## Решение (2 минути)

### Вариант 1: SQL Editor (Препоръчително) ✅

1. **Отворете Supabase Dashboard:**
   👉 https://supabase.com/dashboard/project/hvymzhxefbtyrczrpjjv/sql/new

2. **Копирайте и поставете кода от `STORAGE_SETUP.sql`**

3. **Кликнете `Run` бутона**

4. **Готово!** Тествайте качването на файлове

---

### Вариант 2: Dashboard UI (Визуален начин)

1. **Отворете Storage настройките:**
   👉 https://supabase.com/dashboard/project/hvymzhxefbtyrczrpjjv/storage/policies

2. **Изберете bucket "uploads"**

3. **Кликнете "New Policy"**

4. **Създайте политики за следните операции:**

#### Политика 1: INSERT (Upload)
```
Policy Name: Allow authenticated uploads
Allowed Operation: INSERT
Target roles: authenticated
USING expression: true
WITH CHECK expression:
  bucket_id = 'uploads' 
  AND (storage.foldername(name))[1] = 'requests'
  AND (storage.foldername(name))[2] = auth.uid()::text
```

#### Политика 2: SELECT (Read)
```
Policy Name: Allow users to read own files
Allowed Operation: SELECT
Target roles: authenticated
USING expression:
  bucket_id = 'uploads'
  AND (storage.foldername(name))[1] = 'requests'
  AND (storage.foldername(name))[2] = auth.uid()::text
```

#### Политика 3: UPDATE
```
Policy Name: Allow users to update own files
Allowed Operation: UPDATE
Target roles: authenticated
USING expression:
  bucket_id = 'uploads'
  AND (storage.foldername(name))[1] = 'requests'
  AND (storage.foldername(name))[2] = auth.uid()::text
```

#### Политика 4: DELETE
```
Policy Name: Allow users to delete own files
Allowed Operation: DELETE
Target roles: authenticated
USING expression:
  bucket_id = 'uploads'
  AND (storage.foldername(name))[1] = 'requests'
  AND (storage.foldername(name))[2] = auth.uid()::text
```

## Проверка на грешки

Ако все още има проблем:

1. **Отворете Browser Console** (F12)
2. **Проверете за червени грешки**
3. **Копирайте съобщението за грешка**
4. **Ако виждате:**
   - `403 Forbidden` → Проверете RLS политиките
   - `400 Bad Request` → Проверете MIME types и bucket конфигурация
   - `401 Unauthorized` → Влезте отново в акаунта си
