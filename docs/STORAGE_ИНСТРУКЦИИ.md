# Инструкции за настройка на Storage Bucket в Supabase

## Проблем
Логнатите потребители не могат да качват файлове, защото липсват Row Level Security (RLS) политики за storage bucket "uploads".

## Решение

### Стъпка 1: Отворете Supabase Dashboard
1. Отидете на: https://supabase.com/dashboard/project/hvymzhxefbtyrczrpjjv
2. Влезте с вашия акаунт

### Стъпка 2: Отворете SQL Editor
1. В лявото меню намерете и кликнете на **"SQL Editor"**
2. Кликнете на бутона **"New Query"** горе вдясно

### Стъпка 3: Изпълнете SQL скрипта
1. Отворете файла `database/STORAGE_SETUP.sql` от проекта
2. Копирайте **целия** SQL код от файла
3. Поставете го в SQL Editor прозореца
4. Кликнете на бутона **"Run"** (или натиснете `Ctrl+Enter`)

### Стъпка 4: Проверете резултатите
След изпълнението на скрипта, трябва да видите:
- ✅ Съобщение за успешно изпълнение
- ✅ Списък с създадени политики
- ✅ Информация за bucket конфигурацията

### Какво прави този скрипт?
SQL скриптът създава следните RLS политики:

1. **Users can upload files to their own folder**
   - Позволява на регистрирани потребители да качват файлове в `uploads/requests/{user_id}/`

2. **Users can read their own files**
   - Позволява на потребителите да виждат собствените си качени файлове

3. **Users can update their own files**
   - Позволява на потребителите да актуализират собствените си файлове

4. **Users can delete their own files**
   - Позволява на потребителите да изтриват собствените си файлове

5. **Admins can read all files**
   - Позволява на администраторите (super_admin, moderator) да виждат всички качени файлове

6. **Admins can delete all files**
   - Позволява на администраторите да изтриват всички файлове

7. **Public can view uploads bucket**
   - Позволява публичен достъп за преглед на bucket информация

### Стъпка 5: Тествайте качването на файлове
1. Презаредете вашето приложение: http://localhost:5174/
2. Влезте с потребителски акаунт
3. Отидете на страницата "Качване": http://localhost:5174/upload.html
4. Опитайте да качите STL, OBJ или SVG файл
5. Проверете дали качването е успешно

## Често задавани въпроси

### Защо не мога да приложа миграцията автоматично?
Storage таблиците (`storage.objects`, `storage.buckets`) се управляват от Supabase система и не могат да бъдат променяни директно чрез обикновени миграции. Затова е необходимо ръчно изпълнение чрез SQL Editor.

### Какво ще стане ако вече има създадени файлове?
Скриптът включва `DROP POLICY IF EXISTS` команди, които безопасно изтриват старите политики преди да създадат новите. Съществуващите файлове няма да бъдат засегнати.

### Как мога да проверя дали политиките са активни?
В SQL Editor изпълнете:
```sql
SELECT * FROM pg_policies WHERE schemaname = 'storage';
```

### Мога ли да направя bucket-а публичен?
**НЕ се препоръчва!** Вместо това използвайте RLS политиките, за да контролирате точно кой има достъп до кои файлове.

## Поддръжка
Ако проблемът продължава след изпълнението на SQL скрипта:

3. Уверете се че вашият потребител е в `profiles` таблицата
4. Проверете дали `.env` файлът съдържа правилните Supabase credentials
